# 前端调试技巧
骨灰级调试大师Alert
------------
https://mbos.kdeascloud.com/doc/wiki.html?key=debugTips

互联网刚刚起步的时代，网页前端还主要以内容展示为主，浏览器脚本还只能为页面提供非常简单的辅助功能的时候。那个时候，网页主要运行在以IE6为主的浏览器中，JS的调试功能还非常弱，只能通过内置于Window对象中的alert方法来调试。

```
var aa ="aaa";
alert(aa);

```

```
alert的调试方式很原始,窗口不太美观而且会遮挡部分页面内容,开发人员调试完成后，必须手动清除这些调试代码，除了用于手机端调试，其他情况下不建议使用。

```

新一代调试王者Console
--------------

新一代的浏览器Firefox、Chrome，包括IE，推出了JS调试控制台，支持使用在js代码哩以类似”console.log(xxxx)”的形式，在控制台（F12 ->Console）打印调试信息，而不直接影响页面显示.。

```
console.log(location.href);

```

好吧，再见丑陋的alert弹出框。而以Chrome浏览器为首的后起之秀，为Console扩展了更丰富的功能：

```
console.table([[1,2,3,4],['a','b','c','d']]);
console.table([{a:1,b:2,c:3}]);
console.error('error');
console.warn('error');

```

你以为这样就满足了？Chrome开发团队的想象力实在不得不让人佩服：

```
console.log("%c测试文案","font-size: 50px;text-shadow:0 0 5ox #f00");

```

```
console其实不删除也不会对业务逻辑造成破坏。当然，为了代码整洁，在调试完成后，还是应尽可能删除这些与业务逻辑无关的调试代码。

```

JS断点调试
------

### Sources断点

JS断点调试，即是在浏览器开发者工具中为JS代码添加断点，让JS执行到某一特定位置停住，方便开发者对该处代码段的分析与逻辑处理。

```
mbos这里显示打断点调试的功能，需要点击预览->调试窗口打开->f12

```

![](https://mbos.kdeascloud.com/mbos/store/wikiImg/1505197119931.png)

```
图上的这一步，是我们先打开f12，然后找到Sources 目录，在左侧找到mbos文件树，打开它的子文件store，下面一般有两个文件。第一个是以企业号/项目编码/目录编码为文件夹名称，展开文件夹一般有两个文件，都是以文件编码开头，但第一个是文件保存的是事件的编码内容，第二个文件保存的文件CSS的编码内容。找到事件编码后，就可以打开事件，在外面想要打断点的地方找打上断点，这个和eclipse类似。

```

### Debugger断点

所谓的Debugger断点，专业术语我也不知道怎么说。具体的说就是通过在代码中添加"debugger;"语句，当代码执行到该语句的时候就会自动断点。接下去的操作就跟在Sources面板添加断点调试几乎一模一样，唯一的区别在于调试完后需要删除该语句。我觉得最方便的是这种打断点的方式，只需要打开f12。操作出发了断点就会自动在debugger；那一行打上断点，，不需要花费时间去一步一步找到文件再打断点。

![](https://mbos.kdeascloud.com/mbos/store/wikiImg/1505197471079.png)

```
我们在开发中偶尔会遇到异步加载html片段（包含内嵌JS代码）的情况，而这部分JS代码在Sources树种无法找到，因此无法直接在开发工具中直接添加断点，那么如果想给异步加载的脚本添加断点，此时"debugger;"就发挥作用了

```
